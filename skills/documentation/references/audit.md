# Аудит документации

Два режима: **аудит** (нашли отсутствующее/устаревшее) и **генерация** (создали/
обновили). В обоих — сначала вердикт, потом детали. Правки в файлы — по согласованию.

## Режим аудита

```markdown
## Аудит документации — вердикт

**Состояние доков:** ПЛОХО / ЕСТЬ ПРОБЕЛЫ / ОК
**Проект:** FastAPI-сервис аналитики · Python 3.12 · systemd-деплой
**Проверено:** README, docs/adr/ (2 шт.), docstrings в app/services/

Одной строкой: где документация врёт или чего критично не хватает.

---

## Находки

### CRITICAL — README указывает несуществующую команду запуска

- **Где:** `README.md`, секция «Быстрый старт»
- **Что не так:** `python main.py` — такого файла нет; точка входа `app/main.py` под uvicorn.
- **Почему важно:** агент/будущий ты не запустит проект.
- **Как исправить:** заменить на `uvicorn app.main:app --reload`; сверить с кодом.

### HIGH — выбор Postgres вместо SQLite нигде не зафиксирован

- **Где:** `docs/adr/` (ADR отсутствует)
- **Что не так:** нетривиальное решение без причины.
- **Как исправить:** завести `docs/adr/0001-use-postgres.md` по шаблону.

### MEDIUM — нет деплой-заметки в README

### LOW — docstring дублирует type hints

---

## Что предлагаю сгенерировать/исправить

- [ ] Починить команду запуска в README (CRITICAL)
- [ ] ADR-0001 о выборе Postgres (HIGH)
```

## Приоритеты

- **CRITICAL** — док **врёт**: README/ADR противоречит коду (неверная команда,
  несуществующая env, удалённый модуль) → агент/ты сломает прод.
- **HIGH** — нет того, без чего не запустить: README без quick start/env; нет ADR
  для уже принятого нетривиального решения.
- **MEDIUM** — нет деплой-заметки; ADR без «Последствия»/«Альтернативы».
- **LOW** — стиль, формулировки, дублирование type hints в docstring.

## Режим генерации

```markdown
## Документация — сгенерировано

**Проект:** <название/класс>
**Режим:** генерация

### Создано

- `README.md` — назначение, quick start, env, запуск, деплой-заметка systemd.
- `docs/adr/0001-use-postgres.md` — фиксация выбора БД.

### Обновлено

- `app/services/payment.py` — docstrings к публичным функциям (Google-style).

### Требует твоего ввода (не вытащить из кода)

- ADR по async vs sync — нужна мотивация решения.
- Деплой-заметка: подтверди имя systemd-юнита и путь к EnvironmentFile.
```

## Принципы вывода

- **Вердикт первым.**
- **Приоритет по вреду:** врущая документация всегда выше отсутствующей.
- **Конкретика:** файл, секция, что не так и как починить.
- **Не раздувать:** для утилиты на 50 строк отсутствие ADR — не находка; привязывать
  требования к размеру и важности проекта.
- **Документировать «почему».**
- **Правки — по согласованию:** сначала отчёт, потом файлы.
- **Незнакомый проект** — сперва разобраться в коде, иначе документируешь вслепую.

## Чек-лист

- [ ] Вердикт + находки по приоритету.
- [ ] CRITICAL — только реальные расхождения с кодом.
- [ ] Каждая находка: где, что, почему, как исправить.
- [ ] Требования соразмерны проекту.
- [ ] Правки применяются после подтверждения.
