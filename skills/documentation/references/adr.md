# ADR — Architecture Decision Records

ADR — короткая запись о **принятом решении**: контекст, решение, последствия.
Формат — лёгкий MADR. Цель: через полгода вспомнить **почему** и не переоткрывать
закрытые вопросы.

## Когда писать

**Писать**, если решение:

- трудно/дорого откатить (БД, фреймворк, аутентификация, формат API);
- неочевидно и кто-то спросит «почему так»;
- отвергает разумную альтернативу (Postgres vs Mongo; sync vs async; отказ от Celery);
- задаёт правило на весь проект (структура, формат ошибок, стратегия миграций).

**Не писать:** обратимые мелочи, имена переменных, очевидные решения, хаки (это
комментарий/TODO).

> Правило: «Буду ли я помнить причину через 6 месяцев?» Нет → ADR.

## Хранение и нумерация

- Каталог `docs/adr/` в корне.
- Имя: `NNNN-kebab-case-title.md` (`0001`, `0002`), сквозной номер.
- Номер не переиспользуется. Решение отменили — статус `Superseded`, файл живёт.
- Опционально `docs/adr/README.md` — индекс.

```
docs/adr/
├── 0001-use-postgres-not-sqlite.md
├── 0002-fastapi-over-django-for-api.md
└── README.md
```

## Шаблон

```markdown
# NNNN. Краткое решение

- **Статус:** Accepted <!-- Proposed | Accepted | Deprecated | Superseded by ADR-NNNN -->
- **Дата:** 2026-06-16

## Контекст

Какую проблему решаем и в каких условиях: требования, ограничения (команда, среда,
деплой, бюджет), факты. Без «решения» — только постановка.

## Решение

Что решили, конкретно, 1–2 абзаца.

## Альтернативы

Что рассматривали и почему отвергли (1–2 строки на вариант) — самое ценное.

- **SQLite** — отверг: нет конкурентной записи.
- **Mongo** — отверг: данные реляционные.

## Последствия

И хорошее, и плохое, честно.

- (+) Транзакции, FK, зрелый стек.
- (−) Нужно поднимать/бэкапить Postgres локально.
- Следствие: миграции → перед прод-деплоем гонять `migration-safety`.
```

## Статусы

- **Proposed** — рассматривается.
- **Accepted** — принято и действует.
- **Deprecated** — не актуально, замены нет.
- **Superseded by ADR-NNNN** — заменено; в новом — ссылка `Supersedes ADR-NNNN`.

**Не редактировать принятое решение задним числом** (кроме опечаток). Передумал —
новый ADR, старый помечаешь `Superseded`. История важнее «чистоты».

## Связь с кодом и доками

- ADR — «почему»; ARCHITECTURE.md — «как устроено сейчас». При расхождении ADR —
  история выбора.
- В коде/PR можно сослаться: `# см. ADR-0002`.
- README ссылается на `docs/adr/` строкой, не пересказывает.

## Аудит ADR

- **HIGH:** крупное необратимое решение без ADR → причина потеряна.
- **MEDIUM:** ADR без «Последствия»/«Альтернативы».
- **LOW:** пропуски в нумерации, нет индекса, статус не обновлён.

## Чек-лист

- [ ] ADR только на нетривиальные решения.
- [ ] Есть контекст, решение, альтернативы, последствия, статус.
- [ ] Нумерация сквозная, в `docs/adr/`.
- [ ] Принятые ADR не редактируются; замены — `Superseded`.
- [ ] README ссылается на ADR, не пересказывает.
