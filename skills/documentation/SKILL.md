# Documentation

README и ADR — страховка «будущего тебя» и топливо для агентов. Цель: за минуту
понять, что это, как запустить и **почему** так решено.

> Docstrings (Google-style, матрица по артефактам) — в навыке `python`,
> `references/documentation.md`.

## Когда применять

- Новый проект без README; README устарел/врёт.
- Принято нетривиальное решение → ADR.
- Аудит документации (что отсутствует/устарело).

## Принципы

1. **Документируй «почему», а не «что».** Код говорит, _что_; док — _почему_.
2. **Устаревший док хуже отсутствующего.** Он врёт — помечай или удаляй.
3. **Минимум воды.** Никакой маркетинговой прозы.
4. **Близко к коду.** README — в корне; ADR — в `docs/adr/`.
5. **Не дублировать код/конфиги** — ссылаться.
6. **Конкретика:** файл, секция, что не так и как починить.

## README

Порядок секций (сверху — самое нужное):

1. Заголовок + компактные бейджи стека.
2. Назначение (1–2 строки) + кросс-ссылки на соседние сервисы (монорепозиторий).
3. Возможности, Технологии.
4. Структура проекта (аннотированное дерево).
5. Локальная установка + таблица сервисов/URL.
6. Контроль качества, Маршруты, Management-команды, env.
7. Диаграммы (mermaid) — в `<details>`.
8. Дополнительные ссылки, деплой-заметка.

````markdown
# Project Name

Одна-две строки: что это и какую задачу решает.

## Быстрый старт

```bash
git clone <url> && cd project
uv sync
cp .env.example .env
python manage.py migrate        # Django; для FastAPI — свой шаг миграций
python manage.py runserver      # или: uvicorn app.main:app --reload
```
````

| Переменная     | Обязательна | По умолчанию | Назначение          |
| -------------- | ----------- | ------------ | ------------------- |
| `DATABASE_URL` | да          | —            | DSN Postgres        |
| `SECRET_KEY`   | да          | —            | секрет приложения   |
| `LOG_LEVEL`    | нет         | `INFO`       | уровень логирования |

## Деплой

- systemd-юнит, `EnvironmentFile` с секретами (не в репозитории).
- Перезапуск: `sudo systemctl restart project`; логи: `journalctl -u project -f`.

````

- Длинные/опциональные блоки (команды, диаграммы, большие таблицы) — в `<details>`,
  чтобы README оставался сканируемым.
- Бейджи — компактный ряд стека, без «бейджей ради бейджей».
- Список env должен совпадать с `.env.example` и кодом.
- Адаптация: Django — `migrate`/`runserver`/gunicorn; FastAPI — `--reload`/gunicorn;

## ADR

ADR — короткая запись о **принятом решении**: контекст, решение, последствия.
Формат — лёгкий MADR.

**Писать**, если решение:
- трудно/дорого откатить (БД, фреймворк, аутентификация, формат API);
- неочевидно («почему так, а не иначе»);
- отвергает разумную альтернативу;
- задаёт правило на весь проект (структура, формат ошибок, стратегия миграций).

**Не писать** для обратимых мелочей и очевидных решений.

Хранение: `docs/adr/NNNN-kebab-title.md`, сквозной номер, не переиспользуется.
Статусы: `Proposed` / `Accepted` / `Deprecated` / `Superseded by ADR-NNNN`.
Принятое решение не редактировать — новое ADR, старое помечать `Superseded`.

```markdown
# 0002. Доступ к данным во FastAPI

- **Статус:** Accepted
- **Дата:** 2026-01-01

## Контекст
Схемой и миграциями владеет Django; FastAPI — потребитель.

## Решение
FastAPI читает через SQLAlchemy ORM поверх существующих таблиц, без миграций.

## Альтернативы
- **Core-only** — отверг: ручной маппинг, дублирование.
- **Свои миграции** — отверг: дублирование схемы.

## Последствия
- (+) Нет дублирования схемы.
- (−) Маппинг нужно синхронизировать с Django.
````

Подробно: [references/adr.md](references/adr.md).

## Аудит документации

Приоритет по вреду:

- **CRITICAL** — док **врёт**: README/ADR противоречит коду (неверная команда,
  несуществующая env, удалённый модуль).
- **HIGH** — нет того, без чего не запустить: README без quick start/env; нет ADR
  для уже принятого нетривиального решения.
- **MEDIUM** — нет деплой-заметки; ADR без «Последствия»/«Альтернативы».
- **LOW** — стиль, формулировки.

Формат: сначала вердикт, потом находки по убыванию; правки — по согласованию.

Подробно: [references/audit.md](references/audit.md).

## Запрещённые паттерны

| ❌ Запрещено                             | ✅ Правильно                                |
| ---------------------------------------- | ------------------------------------------- |
| README противоречит коду                 | сверять с кодом, чинить                     |
| Длинное вступление «в современном мире…» | назначение в 1–2 строках                    |
| Дублировать `requirements`/конфиги       | ссылаться                                   |
| README как runbook                       | деплой-заметка + ссылка на `docs/DEPLOY.md` |
| ADR пересказывает «как»                  | объясняет «почему»                          |
| ADR без альтернатив/последствий          | обязательные разделы                        |
| Редактировать принятый ADR               | новое ADR + `Superseded`                    |
| ADR на обратимую мелочь                  | только нетривиальные решения                |
| «TODO: написать документацию»            | честные строки сейчас                       |

## Чек-лист

- [ ] README: назначение, стек, quick start, env, запуск, деплой-заметка, ссылка на архитектуру.
- [ ] Команды и env в README реально существуют в коде.
- [ ] Нетривиальные решения зафиксированы в `docs/adr/`.
- [ ] ADR содержат контекст, решение, альтернативы, последствия, статус.
- [ ] Принятые ADR не редактировались; замены помечены `Superseded`.
- [ ] Нет устаревших доков, противоречащих коду.
- [ ] Документируем «почему», без воды.
