# Версионирование

- Версия с первого дня: `/v1`, не `/api`.
- Только мажорные версии (`v1`, `v2`); SemVer — для SDK/пакетов.
- Ломающие изменения — только в новой версии.
- Не более 2–3 активных версий; окно депрекации ≥ 6 месяцев.
- Версионирование применяется ко **всему** API, не по эндпоинту.

## Breaking vs non-breaking

**Breaking (новая версия):**
- удаление/переименование полей или эндпоинтов;
- смена типа поля/структуры ответа;
- новый обязательный параметр запроса;
- смена статус-кода для того же сценария;
- смена механизма аутентификации.

**Non-breaking (та же версия):**
- новые эндпоинты;
- новые опциональные поля запроса;
- новые поля ответа (клиент игнорирует неизвестные);
- багфиксы, производительность.

## Стратегии

| Стратегия | Пример | Плюсы | Минусы |
|---|---|---|---|
| URI | `/v1/users` | явно, легко роутить/кэшировать | не «чистый» REST |
| Header | `API-Version: 1` | стабильные URI | скрыто, сложнее отлаживать |
| Media type | `Accept: application/vnd.api.v1+json` | content negotiation | сложно |
| Query | `/users?version=1` | просто | засоряет query |

**Рекомендация — URI-версия** как самая явная.

```python
app = FastAPI()
v1 = APIRouter(prefix="/v1")
v2 = APIRouter(prefix="/v2")

app.include_router(v1)
app.include_router(v2)
```

Общую логику выносить в сервисы; версионные — только модели ответа.

## Deprecation / sunset

```http
Deprecation: true
Sunset: Wed, 15 Jan 2025 00:00:00 GMT
Link: </v2/users/123>; rel="successor-version"
```

```python
@v1.get("/users/{user_id}", deprecated=True)
async def get_user_v1(user_id: int, response: Response) -> UserV1:
    response.headers["Deprecation"] = "true"
    response.headers["Sunset"] = "Wed, 15 Jan 2025 00:00:00 GMT"
    response.headers["Link"] = f'</v2/users/{user_id}>; rel="successor-version"'
    ...
```

После sunset — `410 Gone` с ссылкой на миграцию (не `404`).

## Политика

1. Анонс депрекации ≥ 6 месяцев.
2. Обе версии работают 6–12 месяцев.
3. Публикация даты sunset.
4. Grace-период ~30 дней `410 Gone` перед выключением.

## Discovery и миграция

- `GET /` — список версий со статусом/sunset/документацией.
- `GET /v1/version` — версия, дата, статус, sunset.
- Гайд по миграции (старый vs новый payload, маппинг полей); обновление SDK.
- Трекинг использования по версиям перед sunset.

## Антипаттерны

| ❌ | ✅ |
|---|---|
| Версия «потом» | `/v1` сразу |
| Ломать поле без новой версии | новая версия |
| Версионирование по эндпоинтам | единая стратегия |
| Молчаливое удаление | `Deprecation`/`Sunset` |
| `404` после sunset | `410 Gone` |
| Много активных версий | ≤ 3 |

## Чек-лист

- [ ] API стартует с `/v1`; только мажорные версии.
- [ ] Ломающие изменения — новая версия.
- [ ] Стратегия консистентна.
- [ ] Deprecation/Sunset/Link на устаревших маршрутах.
- [ ] `410 Gone` после sunset с гайдом миграции.
- [ ] Discovery-эндпоинт и план миграции.
