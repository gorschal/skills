# Стиль NatSpec для Solidity

Единый стиль комментариев во всех `.sol`-файлах (src, scripts, tests).

## Правила

### 1. Разделители блоков

`=` заменяется на `-`.

```solidity
// ============ Внешние функции ============
```

→

```solidity
// ------------ Внешние функции ------------
```

### 2. Однострочный NatSpec

Однострочный докстринг остаётся в виде `/// @...` (не превращается в блок).

```solidity
/// @notice Адрес казначейского кошелька
```

### 3. Многострочный NatSpec

Последовательность из 2+ строк `/// @...` превращается в блок `/** ... */`:

```solidity
/// @notice Пополнение контракта токенами (через approve + transferFrom)
/// @param token Адрес токена для депозита
/// @param amount Сумма для депозита
```

→

```solidity
/**
 * @notice Пополнение контракта токенами (через approve + transferFrom)
 * @param token Адрес токена для депозита
 * @param amount Сумма для депозита
*/
```

### 4. Существующие блоки `/** ... */`

Все многострочные блоки нормализуются к единому виду:
- открытие `/**`;
- каждая строка контента с префиксом ` * ` (с сохранением отступа контента);
- закрытие `*/` на отдельной строке ровно под открытием `/**` (тот же отступ,
  без лишнего пробела).

```solidity
    /**
     * @notice Инициализация контракта
     * @param _keeper Адрес кипера
    */
```

## Границы применения

- Трогать только файлы проекта: `src/`, `scripts/`, `tests/`.
- **Не** трогать `lib/` (зависимости, например OpenZeppelin) и прочие внешние
  библиотеки.
- Не менять логику кода, только комментарии.
- Пресервить незакоммиченные изменения pragma/кода в рабочем дереве.

## Проверка

После преобразования собрать проект (например `forge build`) — должны остаться
только pre-existing предупреждения компилятора, не связанные с комментариями.
