# Коммиты (конвенция проекта)

Формат сообщения:

```
<тип>(<scope>): <описание в инфинитиве>
```

- `scope` — подсистема/компонент монорепозитория: `django`, `fastapi`, `foundry`,
  `bdd`, `docker`, `ci`, `deps`.
- Описание — **в инфинитиве** («Что сделать?»): «настроить», «устранить»,
  строчными буквами, без точки в конце.

## Основные типы

| Тип | Назначение |
|---|---|
| `feat:` | новая функциональность для пользователя |
| `fix:` | исправление ошибки |
| `docs:` | обновление документации (README, docstrings, комментарии) |
| `style:` | изменения, не затрагивающие логику (форматирование, линтинг) |
| `refactor:` | рефакторинг без изменения функциональности |
| `test:` | добавление или изменение тестов |
| `chore:` | зависимости, CI, сборка, вспомогательные задачи |
| `revert:` | откат предыдущего коммита |

CI/сборка/зависимости идут под `chore:` (отдельных `build`/`ci` нет).

## Как НАДО

```
feat: настроить валидацию формы
fix(django): устранить утечку памяти на главной странице
refactor(fastapi): упростить логику расчета скидки
test(contracts): добавить кейс для нулевой комиссии
test(bdd): уточнить шаг ретрая вебхука
style(bdd): поправить форматирование шагов
```

## Как НЕ надо

- `fix: Исправил баг.` — заглавная буква, прошедшее время, точка в конце.
- `feat: добавляет авторизацию` — настоящее время.
- `правки` — неинформативно, без типа.

## Footer (дополнительная информация)

Когда важно для контекста — строки-футеры:

```
feat(auth): добавить вход через Google

Closes: ANEEPAY-123
Co-authored-by: ...
```

- `Closes:`/`Refs:` — привязка к задаче/issue.
- `Co-authored-by:` — реальный соавтор; не добавлять как AI-подпись без
  необходимости.
- `BREAKING CHANGE:` — ломающее изменение (что сломалось и как мигрировать).

## Правила

- Один коммит — один логический change; смешение типов недопустимо.
- Тело (если есть) объясняет **почему**, не пересказывает дифф.
- Стиль сверять с `git log` репозитория.

## Антипаттерны

| ❌ | ✅ |
|---|---|
| `fix: Исправил баг.` | `fix(django): устранить ...` |
| `feat: добавляет авторизацию` | `feat: добавить авторизацию` |
| `правки` | `refactor(api): ...` |
| `update`/`WIP` | конкретный тип + инфинитив |
| `perf:`/`build:`/`ci:` | `chore:` (в этой конвенции) |
| Смешение feat+docs+test | отдельные коммиты |

## Чек-лист

- [ ] `<тип>(<scope>): <инфинитив>`, строчными, без точки.
- [ ] Тип из списка; scope — подсистема монорепозитория.
- [ ] Тело — «почему»; футеры `Closes:`/`Co-authored-by:` при необходимости.
- [ ] Стиль совпадает с `git log`.
