# Ручной review — 8 испытаний

Оцени каждую категорию 0–10. Для находки: файл, строка, проблема, решение.

## 1. Архитектура (0-10)

- Чёткое разделение слоёв (router/handler → service → repository → schemas).
- Нет бизнес-логики в обработчиках/views.
- DI (FastAPI `Depends`, конструкторы сервисов).
- Конфигурация из env (`pydantic-settings`), не хардкод.
- Нет циклических импортов.
- Единая точка входа, понятная структура.

**Антипаттерны:** God-objects, логика в `__init__.py`, хардкод URL/секретов.

## 2. Обработка ошибок (0-10)

- Доменные exception-классы.
- Глобальный error handler (RFC 7807 для API, HTML для Django).
- Нет голых `except:`/`except Exception:`.
- Корректные статус-коды; нет утечки стектрейсов.
- Логирование с контекстом (не `print`).
- Graceful degradation при недоступности внешних сервисов.

**Антипаттерны:** `pass` в except, проглатывание ошибок, 500 на всё, трейсбеки в ответах.

## 3. Безопасность (0-10)

- Валидация входа (Pydantic/формы).
- SQL-инъекции закрыты (ORM/параметры).
- Аутентификация/авторизация (JWT/OAuth2/RBAC, проверка владельца).
- CORS не `allow_origins=["*"]` в проде.
- Секреты в env, не в коде.
- Rate limiting, HTTPS-only, защита от SSRF/XSS/CSRF.

**Антипаттерны:** секреты в git, `DEBUG=True` в проде, `eval`/`exec`.
Подробнее — навык `security`.

## 4. Производительность и Highload (0-10)

- Async/await для I/O; нет блокирующих вызовов в `async def`.
- Пул соединений БД.
- Индексы на частых полях; нет N+1 (`select_related`/`prefetch_related`,
  `joinedload`/`selectinload`).
- Кэш (Redis) где уместно.
- Пагинация на всех list-эндпоинтах.
- Тяжёлое — в фоне (Django Tasks/очередь), не в запросе.
- Streaming для больших ответов.

**Антипаттерны:** sync в async, загрузка всей таблицы в память, нет лимитов размера.

## 5. Тестирование (0-10)

- Покрытие критичных путей; BDD — основное покрытие, unit — пробелы.
- Тесты проверяют поведение, а не моки.
- Фикстуры/фабрики; edge-cases и ошибки.
- Изоляция; нет зависимости от порядка/внешних сервисов.

**Антипаттерны:** `assert True`, тесты зависят от порядка, ходят в реальную БД.
Подробнее — `python-testing`, `pytest-bdd`.

## 6. Инфраструктура и деплой (0-10)

- Dockerfile (multi-stage, `.dockerignore`).
- docker-compose для локалки.
- CI/CD настроен.
- Миграции управляемые (Django migrations; схема — Django).
- Health-check, graceful shutdown.
- Конфигурация по окружениям (dev/staging/prod).

**Антипаттерны:** `pip install` в CMD, root в контейнере, нет `.dockerignore`,
миграции вручную.

## 7. Качество кода и стиль (0-10)

- Единый стиль (`ruff format`), `ruff check` зелёный.
- Type hints на публичных функциях, `pyright` зелёный.
- Docstrings на сложной логике.
- Нет магических чисел/строк (константы/enum).
- Файлы < ~300 строк, функции < ~30 (в среднем).
- Понятные имена.

**Антипаттерны:** `x`/`data`/`result` без контекста, файлы 1000+ строк, копипаста.

## 8. Документация и DX (0-10)

- README с запуском и env.
- API-документация (OpenAPI/ReDoc или аналог).
- `.env.example` с описанием переменных.
- ADR для нетривиальных решений.
- Комментарии объясняют «почему».

**Антипаттерны:** «запусти и разберёшься», недокументированные env, устаревший README.
Подробнее — навык `documentation`.
