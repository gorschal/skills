# Security review

Формализованный процесс: сначала инструменты, потом ручной разбор (они не видят
контекст), затем классификация и отчёт.

## Процесс

1. **Scope** — карта поверхности атаки и критических путей. Для активного
   тестирования — письменная авторизация и правила engagement.
2. **Scan** — SAST, зависимости, секреты.
3. **Manual review** — auth, обработка ввода, крипто, доступ к объектам.
4. **Classify** — severity по CVSS; PoC только в пределах scope.
5. **Report** — файл/строка, impact, remediation; критические — сразу.

## Инструменты

```bash
semgrep --config=auto .          # SAST
bandit -r src                    # Python SAST
uv run ruff check --select S     # flake8-bandit
uv run pip-audit                 # уязвимые зависимости
gitleaks detect --source=.       # секреты
trivy fs .                       # зависимости/конфиги/образы
```

## Ручной чек-лист

- **Auth**: хеширование, rate limit/lockout, JWT/сессии, общие ошибки.
- **Authorization**: проверка владельца/роли на каждом объекте (IDOR).
- **Input**: SQL/команды/шаблоны, path traversal, SSRF, десериализация, загрузки.
- **Crypto/secrets**: алгоритмы, TLS, секреты вне кода, отсутствие в логах.
- **Config**: `DEBUG`, `ALLOWED_HOSTS`, CORS, headers, cookies.
- **Logging**: security-события логируются, PII — нет.

## Severity (CVSS)

| Уровень  | Ориентир                                            |
| -------- | --------------------------------------------------- |
| Critical | RCE, полный обход auth, массовая утечка             |
| High     | SQLi/IDOR с доступом к данным, эскалация привилегий |
| Medium   | ограниченная утечка, CSRF, слабая конфигурация      |
| Low      | информационные утечки, best-practice отступления    |
| Info     | замечания без прямого риска                         |

## Формат находки

```
ID: FIND-001
Severity: High (CVSS 8.1)
Title: SQL Injection in user search
File: src/api/users.py, line 42
Description: Ввод конкатенируется в SQL без параметризации.
Impact: Чтение/изменение/удаление данных БД.
Remediation: Параметризовать запрос / использовать ORM.
References: CWE-89, OWASP A03:2021
```

## Структура отчёта

1. Executive summary с оценкой риска.
2. Таблица находок со счётчиками по severity.
3. Детализация: location, impact, remediation.
4. Приоритизированные рекомендации.

## Принципы

- Сначала auth/authz, затем остальное.
- Инструменты **до** ручного разбора, но ручной разбор обязателен.
- Конкретика: файл/строка, а не «улучшите безопасность».
- Критические находки сообщать немедленно.
- Не тестировать прод без авторизации; PoC — не выходить за рамки.

## Чек-лист

- [ ] Определён scope и авторизация.
- [ ] Запущены SAST/SCA/secret-scan.
- [ ] Проведён ручной разбор auth/authz/ввода/крипто.
- [ ] Находки классифицированы по severity (CVSS).
- [ ] Каждая находка содержит location/impact/remediation.
- [ ] Критические сообщены немедленно.
