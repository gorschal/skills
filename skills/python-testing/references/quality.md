# Качество тестов и антипаттерны

## Главный принцип

**Тестируй то, что делает код, а не то, что делают моки.** Тесты, проверяющие
поведение моков, дают ложную уверенность и не ловят баги.

## Пять антипаттернов

### 1. Тестирование моков

```python
# ❌ проверяем только вызов
def test_get_user(repo):
    service = UserService(repo)
    service.get_user(1)
    repo.get.assert_called_with(1)      # это тест мока, не поведения

# ✅ проверяем результат
def test_get_user(repo):
    repo.get.return_value = {"id": 1, "name": "Alice"}
    service = UserService(repo)
    assert service.get_user(1).name == "Alice"
```

### 2. Тест-онли методы в продакшене

`_reset_for_testing()`/`_set_for_test()` в боевом классе — загрязнение.
Использовать свежие инстансы/тестовые утилиты.

### 3. Мокирование без понимания

«Замокаем всё» → тест зелёный, баг в проде. Сначала прогнать с реальными
зависимостями, потом мокать на границе (внешнее), а не внутреннюю логику.

### 4. Неполные моки

Мок без полей, которые читает код, → прод падает. Использовать фабрики с полным
контрактом.

### 5. Тесты как «потом»

Фича без теста не считается готовой. Тесты пишутся вместе с кодом.

## Флаки-тесты

- Не «перезапускать до зелёного» — изолировать и починить причину.
- Частые причины: порядок тестов, общий state, реальное время/сеть, гонки,
  неочищенные ресурсы.
- Карантин (`@pytest.mark.flaky`/skip) — временно, с задачей на фикс.

## Детект

| Симптом | Антипаттерн |
|---|---|
| Только `mock.assert_called` без проверки результата | тест моков |
| `_reset()`, `_setForTest()` в коде | тест-онли методы |
| 10+ моков в тесте | over-mocking |
| Мок `{"success": true}` без полей | неполный мок |
| Тесты добавлены через недели | тесты «потом» |
| Тест падает вразнобой | флаки/изоляция |

## Пирамида и границы

- BDD — основное сквозное покрытие (навык `pytest-bdd`).
- Unit — логика вне BDD и критичные ветки.
- Интеграционные/e2e — в BDD/QA.
- Unit не дублирует BDD.

## Антипаттерны

| ❌ | ✅ |
|---|---|
| Тест моков | тест поведения |
| Тест-онли методы | свежие инстансы |
| Over-mocking | реальные деп, мок внешнего |
| Неполные моки | фабрики |
| Тесты «потом» | вместе с кодом |
| Игнор флаки | фикс/изоляция |
| `assert result` | конкретный ассерт |

## Чек-лист

- [ ] Тесты проверяют поведение, не моки.
- [ ] Нет тест-онли методов в продакшене.
- [ ] Моки полные; мокается внешнее.
- [ ] Тесты изолированы, не флаки.
- [ ] Unit не дублирует BDD.
